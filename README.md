## О проекте

`stankin_diplom_gravCMS` - итоговая реализация выпускной квалификационной работы, посвящённой управлению информационным наполнением корпоративного веб-сайта без необходимости обращаться к разработчику для каждого изменения.

Основная идея проекта - отделить **программную часть веб-сайта** от **контента**. Разработчик отвечает за архитектуру, шаблоны, плагины и расширение функциональности, а владелец ресурса получает административный интерфейс, через который может самостоятельно:

- редактировать текстовые материалы;
- загружать фотографии и документы;
- публиковать видеоматериалы;
- управлять портфолио и карточками проектов;
- изменять контактную информацию;
- изменять координаты организации на карте;
- добавлять клиентов, партнёров и сертификаты;
- управлять содержимым главной страницы;
- принимать заявки пользователей;
- изменять контент без прямой работы с исходным кодом и файловой системой.

Проект построен на **flat-file архитектуре Grav CMS**. Реляционная база данных для хранения контента не используется: страницы, метаданные, конфигурация и медиафайлы хранятся непосредственно в файловой структуре проекта.

### Решаемая проблема

При традиционной модели сопровождения даже небольшое изменение контента может требовать обращения к разработчику:

```text
Владелец сайта
      |
      v
Формулирование задачи
      |
      v
Передача материалов разработчику
      |
      v
Ожидание выполнения
      |
      v
Внесение изменений
      |
      v
Проверка результата
```

Это приводит к:

- зависимости владельца от технического специалиста;
- задержкам публикации актуальной информации;
- дополнительным расходам на сопровождение;
- риску ошибок при передаче правок;
- снижению оперативности управления веб-ресурсом.

В разработанном решении контент изменяется непосредственно через Grav Admin:

```text
Владелец сайта
      |
      v
Административная панель /admin
      |
      v
Редактирование данных
      |
      v
Сохранение Markdown / YAML / Media
      |
      v
Обновлённая страница
```

Перед разработкой были рассмотрены несколько подходов:

|---|---:|---:|---:|---:|
| Статический сайт | Низкая | Простая | Средняя | Среднее |
| CMS с БД | Высокая | Средняя | Высокая | Среднее |
| **Flat-file CMS** | **Высокая** | **Простая** | **Высокая** | **Простое** |
| Конструктор сайтов | Средняя | Простая | Низкая | Простое |
| Индивидуальный Backend + Frontend | Высокая | Сложная | Высокая | Сложное |

Также сравнивались:

- Grav CMS;
- WordPress;
- Kirby CMS;
- 1С-Битрикс;
- Tilda;
- индивидуальная разработка на Python + React.

Для проекта был выбран **Grav CMS**, поскольку он сочетает:

- отсутствие обязательной СУБД;
- готовую административную панель;
- расширяемые Blueprint-формы;
- файловую модель хранения данных;
- высокую производительность;
- низкие требования к серверной инфраструктуре;
- возможность глубокой кастомизации;
- бесплатную лицензию MIT.

# Функциональность

## Административная панель

Управление контентом выполняется через Grav Admin по адресу:

```text
/admin
```

Для разных типов страниц реализованы специализированные **Blueprint-формы**:

```text
user/blueprints/pages/
├── certificates.yaml
├── contacts.yaml
├── home.yaml
├── partners.yaml
├── portfolio-item.yaml
├── reels.yaml
├── reviews.yaml
├── service-module.yaml
└── stand-page.yaml
```

Blueprint определяет, какие поля владелец увидит в административной панели и какие данные сможет изменять.

Таким образом, владелец работает не с YAML или Markdown напрямую, а с обычными полями:

- текст;
- textarea;
- Markdown-редактор;
- выпадающие списки;
- переключатели;
- загрузка одного или нескольких файлов;
- списки элементов;
- настройки галерей;
- координаты;
- метаданные проекта.

- задавать интервал переключения;

- изменять расстояние между элементами.

# Архитектура

## Flat-file модель

В проекте отсутствует классическая реляционная БД для хранения информационного наполнения.

Основная модель:

```text
Страница сайта = директория + Markdown + YAML metadata + media
```

Пример:

```text
user/pages/
└── 01.home/
    ├── default.ru.md
    ├── image.jpg
    └── video.mp4
```

Числовые префиксы директорий используются Grav для порядка страниц:

```text
01.home
02.o-kompanii
03.uslugi
...
```

---

## Общая схема системы

```mermaid
flowchart TD
    Owner[Владелец сайта] --> Admin[Grav Admin /admin]

    Admin --> BP[Blueprint forms]
    BP --> Data[Markdown + YAML]
    BP --> Media[Media files]

    Visitor[Посетитель] --> Web[Nginx / Web server]
    Web --> PHP[PHP-FPM]
    PHP --> Core[Grav Core]

    Data --> Core
    Media --> Core

    Core --> Page[Page object]
    Page --> Twig[Twig templates]
    Twig --> HTML[HTML / CSS / JavaScript]
    HTML --> Visitor

    Visitor --> Form[Grav Form]
    Form --> Storage[Local form storage]
    Form --> Email[Email plugin / SMTP]
```

---

## Формирование пользовательской страницы

При обращении пользователя:

1. браузер отправляет HTTP-запрос;
2. веб-сервер передаёт запрос PHP;
3. Grav Core определяет нужную страницу;
4. загружается Markdown и YAML;
5. формируется объект `Page`;
6. данные передаются Twig;
7. Twig формирует HTML;
8. результат возвращается браузеру;
9. при включённом кэшировании повторный запрос обрабатывается быстрее.

Схематично:

```text
HTTP Request
    |
    v
Nginx / PHP-FPM
    |
    v
Grav Core
    |
    v
Markdown + YAML + Media
    |
    v
Page
    |
    v
Twig
    |
    v
HTML Response
```

# Локальный запуск

## Требования

Проект основан на стандартном окружении Grav.

Минимально необходимы:

- PHP `7.3.6+` или PHP `8.x`;
- Composer;
- PHP extensions, необходимые Grav;
- Git;
- Bash для `run-local.sh`.

Для разработки рекомендуется PHP 8.x.

## 1. Клонирование

```bash
git clone https://github.com/kemuri-ni-deteitta/stankin_diplom_gravCMS.git
cd stankin_diplom_gravCMS
```

## 2. Установка PHP-зависимостей

```bash
composer install
```

При необходимости также можно использовать стандартные инструменты Grav:

```bash
php bin/grav install
```

## 3. Запуск development server

В репозитории присутствует скрипт:

```bash
chmod +x run-local.sh
./run-local.sh
```

Скрипт:

- использует локальный `php.ini`;
- освобождает порт `8080`, если он занят;
- очищает кэш Grav;
- запускает встроенный PHP-сервер через Grav router.

После запуска:

```text
http://127.0.0.1:8080
```

Административная панель:

```text
http://127.0.0.1:8080/admin
```

> Учётные данные администратора не должны храниться в README или публичном репозитории.

# Production deployment

Рабочая версия проекта была развёрнута на сервере со следующей конфигурацией:

```text
Ubuntu 24.04 LTS
Nginx
PHP 8.3-FPM
Git
Certbot
Let's Encrypt
```

Проект размещался в:

```text
/var/www/litrep
```

Домены:

```text
litrep.ru
www.litrep.ru
```

Для сайта настроено:

- DNS;
- Nginx;
- PHP-FPM;
- SSL;
- перенаправление HTTP -> HTTPS;
- права доступа для Grav;
- обновление программной части через Git.

### Разделение сопровождения

```text
Разработчик
    |
    +-- Twig templates
    +-- PHP / plugins
    +-- CSS / JavaScript
    +-- configuration
    +-- Git deployment

Владелец сайта
    |
    +-- pages
    +-- texts
    +-- images
    +-- videos
    +-- portfolio
    +-- contacts
    +-- forms content
       through /admin
```

Главный принцип сопровождения: **контент и программная часть обновляются независимо друг от друга**.

# Кэширование и оптимизация

В конфигурации Grav включены:

```yaml
cache:
  enabled: true

twig:
  cache: true
  autoescape: true

assets:
  css_minify: true
  js_pipeline: true
  js_minify: true
```

Для изображений используются настройки качества и автоматического исправления ориентации.

После изменения конфигурации или шаблонов кэш можно очистить:

```bash
php bin/grav clearcache
```

# Безопасность

В проекте предусмотрены базовые механизмы защиты:

- доступ к административной панели только после авторизации;
- HTTPS в production;
- Twig autoescape;
- ограничения на допустимые типы загружаемых файлов;
- ограничения размера загрузок;
- серверная валидация форм;
- разделение контента и программного кода.

Конфиденциальные значения, такие как SMTP credentials и данные административных аккаунтов, не должны публиковаться в открытом репозитории.


```text
system/
```
